# AGENTS.md

Guidance for AI coding agents working in this repository. Workspace-wide rules (data layout, units, parity with LocMoFitPy, working with the owner) are in `../AGENTS.md`; read that first.

## What this is

**LocMoFit.jl** fits a *static* parametric geometric model (a ring or a spherical cap, or a composite of them such as two rings or a cap + ring) to one site's 2D or 3D SMLM localizations by maximum likelihood. The model is a dense set of points ("unit points", scaled/rotated/translated by the parameters); each localization's likelihood is a Gaussian mixture over those points, mixed with a uniform background (`derivations/derivation.qmd`). It is a Julia re-implementation of the MATLAB LocMoFit in `../../MATLAB/SMAP/LocMoFit`, and **LocMoFitPy (`../LocMoFitPy`) mirrors it in JAX** — the two must give the same results.

## Commands

```sh
julia --project=. -e 'using Pkg; Pkg.test()'   # test suite, ~2 min (mostly compiling the gradients)
julia --project=. -e 'using LocMoFit'            # quick load check
```

On Apple Silicon, precompilation prints `CpuId` errors ("does not provide information on cpuid leaf 0x00000004"). They come from a dependency and do not stop LocMoFit from loading.

The examples need `CSV`, `DataFrames` and `GLMakie`, which are not in any project here; they assume the owner's global environment and are run from the repo root (relative CSV paths).

CI and `[compat]` target Julia 1.13 only (see Compatibility in `../AGENTS.md`); do not add code paths for older versions.

## How a fit works

`run_locmofit(model, locs, loc_precisions; params, max_iter, tol, spacing, point_params, dtype, background, fov_volume, history)`:

1. `model` is a `Model` (such as `Ring()` or `Composite(Ring(), SphericalCap())`) or a name: `build_model(name)` → `getfield(LocMoFit, Symbol(name))()`, so **the name string is the name of a model type or preset function** (`"Ring"`, `"DoubleRing"`).
2. `params` is a `NamedTuple` of `ParamToFit(value, prior)`, keyed by the fit's **quantities** (`quantities(model, background)`: `x`, `y`, `z`, a ring's `r`, a cap's `s` and `kappa` (κ′), `axis` as `(theta, phi)`, `sigma`, a composite's `shares` (a tuple), `signal` (the signal fraction, with a background); component k's names get k appended). Value and prior are both in the quantity's own terms, which differ from the optimizer's parameters for four of them: `kappa` is fitted as `eta` (κ′ = tanh η), `axis` as the chart coordinates `vx`, `vy` around its starting value, `shares` as `omega2`, …, and `signal` as `logit_prob`. `specification` turns `params` into the optimizer's terms: starting values (an axis as `theta`, `phi`, or `thetak`, `phik`, which center the chart and are not parameters), held parameters (`Fixed()`), ties (`Tied(:source)`, between quantities of one kind: positions, sizes or curvatures) and priors (all but flat ones); unknown names, a prior that does not fit its quantity (`supports`) and a value outside its quantity's range throw an `ArgumentError`. Starting values = `default_parameters(model, dtype)`, plus `logit_prob = log 9` (signal fraction 0.9) with a background, overridden first by `estimate_start` (`src/start.jl`) for every parameter `params` gives no value for and that is neither held nor a tie's target, then by the values given. An axis given for component 1, or held, is passed to `estimate_start` and replaces the estimated axis.
3. `ParameterMap(θ₀, frozen, tie)`: the optimizer sees only the free parameters `u` (a `ComponentVector`); `full_parameters(u, map)` = base + S·u returns all of them as a `NamedTuple`, with the held values in `base`. A tie `target => source` gives the target a 1 in the source's column of `S`, so it takes the source's value throughout (tied to a held parameter, it is held at that value; ties may chain). A parameter both held and tied and cycles throw an `ArgumentError`.
4. `unit_model(model, θ₀, starts; spacing)` builds the unit points and the charts' frames (`rotmat(θ₀, ϕ₀)`) **once, from the starting values with the ties applied**, as `(points, chart)` (a tuple of them for a composite); `point_params` replaces starting values for this step only, so that sites with different starts can share one point count. Point count = `ceil(circumference/spacing)` or `ceil(area/spacing²)`, the cap's area being 4πs². They are fixed for the whole fit, and `model_points` never changes them. Consequence: the loss value depends on the initial `r`/`s` (or `point_params`) and `spacing`.
5. `Optimization.solve` with BFGS and a backtracking line search (`BFGS_BACKTRACKING`, as in DynMoFit: insensitive to the parameters' different scales) on `objective(p, u₀)`, stopping when no gradient component exceeds `tol` (default 1e-4; a Float32 fit can stop before it, NOTES.md) or after `max_iter` iterations, where `p = (model, parameter_map, unit_model, ranges, locs, loc_prec, background, log_volume, priors)` comes from `fit_problem` (`priors`: a tuple of `PriorTerm`s, one per prior that is not flat) (`ranges`: each component's rows among the concatenated points). Returns a `NamedTuple` `(parameters, signal_fraction, weights, components, loss, model, unit_model, model_points, result, history)`; `components` gives each component in the world frame (`position`, `axis` as a vector and as `theta`, `phi`, and its shape: a ring's `r`; a cap's `s`, `kappa` (κ′), `curvature`, `radius`, `alpha` (the half-angle), `area`). `history` is `nothing` unless `history=true`; then it holds the loss and the parameters of every iteration. Recording them costs nothing measurable (≤ 3% on 200-iteration fits, within timing noise).

The loss (`loss`) = minus the log posterior per localization (`derivations/derivation.qmd`, @eq-full-posterior): each localization's density is π · Σₖ wₖ · (mean over component k's points of the Gaussian) + (1 − π)/V, with π = logistic(`logit_prob`), the shares wₖ = softmax(0, `omega2`, …, `omegaK`) and V the field of view's volume (`fov_volume`; default the localizations' bounding box, a little too small); `background=false` drops the background and the signal fraction. To the log-likelihood it adds the log density of every prior that is not flat, each a density of its quantity (a position, a size's magnitude, κ′ = sign(s)·tanh η, an axis on the sphere, π, the shares) with no Jacobian, so that the fit is the most probable value of the quantities whatever the optimizer's coordinates (`derivations/derivation.qmd`, Priors on every parameter). The default priors: `LogNormal(log(50), 1)` on every ring's radius and cap's scale (median 50 nm; it vanishes at 0, which keeps sizes from collapsing, and replaced the soft penalty sizes ≥ 1 nm on the branch `priors`); `Beta(5, 2)` on π (since 2026-10-28: mode 0.8, worth 5 localizations, so it keeps π inside (0, 1) and pulls it toward 0.8 only on very small sites; the earlier Beta(197, 50) from DynMoFit, worth 245 localizations, biased π by about −0.03 on the benchmark's sites, `chart_cap_2026-10-27.txt`); `Dirichlet(5)` on the shares (since 2026-11-14; it keeps every share above 0, so that a component cannot be switched off: a component far from its localizations otherwise lost its share and was left wherever its start put it, NOTES.md; it moves a share toward 1/K by K(α − 1)(1/K − w)/(n + K(α − 1)) for n signal localizations); flat on positions, axes (uniform on the sphere), κ′ (uniform on (−1, 1)) and the blur. The fitted blur `sigma` (σ) is added to every localization precision **in quadrature** (`1/(2(s² + σ²))`), so the gradient with respect to σ vanishes at σ = 0; σ therefore starts at 1 nm. For 2D data, only the first two rows of the model points are used, and the Gaussians are 2D. The squared distances are formed from differences (not expanded), which keeps the Float32 loss accurate at SMAP's coordinates of tens of µm; Float32 fits far from the origin can still stop early (cap fits at 100 µm up to 2.8× their statistical error from the optimum, `NOTES.md`).

**How the loss is computed.** `loss` builds the model points (`model_points`) and hands them to `log_likelihood`, which loops over the localizations and, for each, over every component's points: one pass for the smallest exponent, one for the terms `exp_nonpositive(q_min - q_m)`, kept in a buffer of M numbers, from which the log-sum-exp follows. `likelihood_pass` with `Val(true)` adds one more pass per localization for the gradient (with respect to the points, σ, the log weights and the two log fractions; `derivations/derivation.qmd`, the gradient of the log-likelihood), so a gradient costs about 1.7 values. Enzyme differentiates everything around the loop (parameters → model points, weights, background, priors) and takes the loop's gradient from the rule in `src/rules.jl`. Both passes vectorize, which needs `@fastmath min` for the smallest exponent (a running maximum or `ifelse` does not vectorize), `exp_nonpositive` instead of `Base.exp` (a table lookup), and `@inbounds` written inside every closure in the loops (it does not reach into them, and a bounds check stops vectorization). The per-pair cost fell from 6.5 ns (value) and 25 ns (gradient) with Enzyme over M×N broadcasts to 1.7 and 2.8 ns in Float64, 0.7 and 1.3 ns in Float32 (`benchmarks/speed/`; the reasons and measurements are in `NOTES.md`). `objective` computes every value together with its gradient and keeps the gradient: the line search asks for a trial point's value and then, having accepted it, for its gradient, which would otherwise cost a second evaluation.

**Many sites.** Each fit runs on one thread. Fitting many sites in parallel with `Threads.@threads` over the sites (one thread per performance core) is 5.7× faster on 8 threads for 80 cap fits, the rest being garbage collection of the model points' arrays, but **it can crash Julia with memory corruption**: twice before the rule ("GC error (probable corruption)", 2026-10-26) and once after it (2026-10-27: malloc detected a corrupted heap, "Illegal instruction", after 22 of the 25 groups of a threaded full accuracy run). It is rare (five cold-start threaded runs and the threaded quick subset with `--check-bounds=yes`, which rules out an out-of-bounds write behind `@inbounds` in the kernel, ran clean) and its cause is not known. Fit one site alone first in any case: compiling the gradient on several threads at once took 40–70 s. Until the crash is understood, separate processes are the safe way to fit sites in parallel.

## Adding or changing a model

Models are plain types used for dispatch; their parameters are not stored in them. A **simple model** (one shape) is `struct M <: SimpleModel end` and defines only its shape, in its own frame (reference point such as a ring's center or a cap's apex at the origin, axis along z): `shape_parameters(::M, dtype)` (a `NamedTuple` of the shape's parameters and defaults), `unit_points(::M, shape; spacing)`, `local_points(::M, unit_points, shape)` (the `3×K` points), `shape_quantities(::M, suffix)` (the shape's quantities with their default priors, as `name => (quantity, prior)`, `suffix` appended to the names) and `shape_summary(::M, shape)` (the shape in the usual terms, for `components`); add an `include` in `src/LocMoFit.jl` and an export. The shared pose and the blur are added for it: its parameters are `(x, y, z, shape..., vx, vy, σ)`, where `vx`, `vy` are the tangent-chart coordinates of its axis around the starting axis (`derivations/derivation.qmd`); `model_points` places it with `chart_rotation`. Parameter names must not end in a digit, since a composite appends the component's number.

A **composite** is `Composite(components...; defaults)`: component 1 is placed by its pose in the world, every other component by its pose in component 1's frame. Each component's parameters get its number appended (`x1, r1, x2, s2, …`), `sigma` is shared, and shape parameters are absolute (radii and scales in nm); equal quantities are expressed with `Tied`. Each component's points are averaged on their own, and the components are weighted by their shares of the signal localizations, softmax(0, `omega2`, …, `omegaK`); the `omegak` are fitted from 0 (equal shares) unless held. A preset is a function returning a composite (`DoubleRing()`, `SpCapRing()`), so that its name works in `run_locmofit`. `component_parameters` and `model_points` of a composite are `@generated` from the component names stored in the type (computed by the constructor), which keeps them type-stable for Enzyme.

- `model_points` must not mutate its unit points; build new arrays. Enzyme differentiates through it. Each array it builds costs an allocation and a shadow in every gradient, so fuse broadcasts where it helps (the cap's `local_points` is one broadcast, which halved a gradient's allocations), and measure: a fused `place` allocated less but was slower.
- Scale with `.*`, not `lmul!`: `lmul!(s, X)` returns early when `s` is exactly 1, so Enzyme gives a zero gradient for a scale parameter at 1. In the Lux version, its `scale!` helper (built on `lmul!`) kept `DoubleRing.r2` and `SpCapRing.c2` at their starting value of 1 in every fit.
- No bounds or penalties (the owner's decision, 2026-11-14: proper priors, no hard bounds): what is known about a quantity is its prior. A new shape declares its quantities in `shape_quantities`: a size as `Size` (default `SIZE_PRIOR`, the log-normal), a curvature-like quantity with its own kind if no existing one fits. The cap's |κ′| < 1 holds through κ′ = tanh η, and the orientation needs no constraint.
- **Mirror every model, default, prior, or loss change in LocMoFitPy** (the branch `priors` is not mirrored yet: LocMoFitPy still has `init_params`, `freeze`, `tie`, `signal_prior`, `share_prior` and the size penalties) (see the parity section in `../AGENTS.md`), or note explicitly that you did not. Features are currently developed here first and ported later; `../LocMoFitPy/JULIA_DIFFERENCES.md` lists what is not ported yet.

## Conventions

- Data are `D×N` matrices (columns are localizations), `D ∈ {2,3}`; precisions are per-axis **standard deviations** of the same shape. Units: nm.
- Style (root `AGENTS.md`, Style guide): code is formatted with JuliaFormatter in Blue style (`.JuliaFormatter.toml`), `julia -e 'using JuliaFormatter; format(["src", "test", "benchmarks", "examples"])'`, which leaves the owner's scratch at the root, `old/` and `scripts/` alone (it does format the gitignored `examples/fit/spcap_video_ROI4.jl`, which was left out on 2026-10-27). Comments and docstrings have one line per paragraph, list item or signature, with no hard line breaks; commented-out code and command lines in comments keep their lines. `jlbridge.py` follows PEP 8, except that its comments and docstrings are not wrapped either.
- Default `dtype` is `Float64` (since 2026-10-29; it was `Float32`), with `Float32` an option: keep functions generic in `T` and convert constants with `T(...)`/`one(T)`.
- **The likelihood's loop has a hand-written Enzyme rule** (`src/rules.jl`): change the gradient in `likelihood_pass` (`component_gradient!`, the derivatives with respect to σ, the weights and the fractions) together with the value; the kernel tests check it against central differences, and the gradient tests check Enzyme's gradient of `loss` through the rule. A new model only defines its points; it needs no rule.
- Public names are ASCII (SciML style: no Unicode in public APIs, since every name must be typeable, also from MATLAB and Python): the parameters (`sigma`, `eta`, `omega2`, …), the quantities of `params` (`axis`, `kappa`, `shares`, `signal`, …) and the axes' angles (`theta`, `phi`), the prior types and their fields (`Watson(theta, phi, kappa)`, `LogNormal(mu, sigma)`, …), and the fields of `components` (`theta`, `phi`, `kappa`, `alpha`), as in LocMoFitPy (2026-10-28). Greek letters remain in local variables, internal code and the derivation, which the guide allows.
- `.gitignore` ignores scratch only at the repo root (`/*.csv`, `/simulation*.jl`, `/plotting*`, `/scratch.jl`, `/TODO.md`), plus `*.mp4` and `*_video_*` (scripts that run on experiment data). Everything under `examples/` other than those is meant to be committed. Experiment data live in `../data/`.
- Ask before adding dependencies. `PythonCall` is a dependency but is not used in `src/`.

## Testing

- `Pkg.test()` passes (336 checks, about 3 minutes). `test/runtests.jl` covers: the log-likelihood kernel (in Float32 at 40 µm against the rounding bound of the derivation; `exp_nonpositive` within one unit in the last place of the exact value; - The tests use fixed inputs, no RNG; the only test dependency is `Test`. If a test needs random numbers, use `StableRNG(seed)` (`Xoshiro` streams are not stable across Julia versions) and ask before adding StableRNGs. Do not tune tolerances to make a test pass.
- `benchmarks/accuracy/` measures bias and scatter over many simulated sites: its quick subset after every change, the full run now and then. To check parity, run a fit on a tutorial site (`examples/data/`) and compare with LocMoFitPy (same CSV, starting values, `spacing`, `dtype`). With BFGS the tutorial fits converge (40–115 iterations, Float64 and Float32) and do not depend on a 10⁻⁹ change of a starting value (final losses within 2·10⁻¹⁰); under L-BFGS they stopped at the iteration limit and were chaotic, the final loss changing by tens of percent. Float32 fits can stop early (the loss stops changing before the gradient reaches `tol`) and still report `Success`: a known issue, accepted (Float64 is the default), measured in `NOTES.md` with possible remedies. Float64 fits are bit-identical across sessions and thread counts. Float32 fits are reproducible only for a fixed `julia -t`: the loss is the same, but Enzyme's compiled gradient differs in its last bits with the thread count (also before the rule), and BFGS takes a different path to the same optimum (the tutorial cap: 44 or 52 iterations, final losses 1·10⁻⁴ apart, far below the statistical error).
